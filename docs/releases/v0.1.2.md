# eudkit 0.1.2 release notes

Released 2026-10-28. This release adds editor hover and signature help to the
shared `eudkit-lsp` server and the VS Code and Zed packages. It is the first
published release that contains them; the `v0.1.1` assets do not.

User documentation:
[`docs/eudkit-lsp-user-guide.md`](../eudkit-lsp-user-guide.md).

## What is new

- **Hover for symbols.** Hovering a canonical or Map Context unit, location, or
  switch string shows the symbol name, whether it is canonical or map-defined,
  and its numeric ID. Map aliases also show the canonical unit name, and Stock
  Unit Filters are identified.
- **Hover for supported calls.** The 16 supported calls show their signature,
  one-line summary, return type, and which parameters accept symbols.
- **Signature help.** Python, TypeScript, TSX, JavaScript, and JSX calls show
  the signature and highlight the active parameter after `(` and `,`. Python
  keyword arguments select the matching parameter.
- **Qualified calls.** TypeScript/JavaScript member calls work when the final
  member name is a supported eudkit API, for example `eudkit.KillUnit(...)` and
  the legacy `eud.KillUnit(...)`. Unrelated members such as `console.log(...)`
  and unsupported APIs such as `eudkit.DisplayText(...)` still return nothing.
- **Per-language parameter names.** Hover and signature help use the SDK names
  in TypeScript/JavaScript (`SetSwitch(switchId, action)`) and the Python names
  in Python (`SetSwitch(switch, state)`).

The release also includes the `v0.1.1` editor MVP: canonical unit completion,
Map Context location/switch completion, canonical fallback without a project,
and advisory Map Symbol and EUD player diagnostics.

## Supported platforms

| Platform | Architecture | `eudkit-lsp` asset |
| --- | --- | --- |
| Windows | x86_64 | `eudkit-lsp-windows-x86_64.exe` |
| Linux | x86_64 | `eudkit-lsp-linux-x86_64` |
| macOS | arm64 | `eudkit-lsp-macos-aarch64` |
| macOS | x86_64 | `eudkit-lsp-macos-x86_64` |

Other combinations are unsupported by the published assets. Use a locally
built `eudkit-lsp` through `eudkit.lsp.path` (VS Code), `EUDKIT_LSP_PATH`
(either editor), or `PATH`.

The VS Code VSIX is platform-neutral. Zed uses the source archive
`eudkit-zed-0.1.2.tar.gz`; installing it as a dev extension requires Rust and
the `wasm32-wasip2` target, but the server itself is a native binary and does
not need Rust.

## Separate binaries

The release publishes two independent binaries:

- **`eudkit`** — the build CLI (`build`, `inspect`, `dump-ir`, `watch`,
  `migrate`). This is not used by either editor extension.
- **`eudkit-lsp`** — the language server used by both editor extensions.

Editor assets:

- `eudkit-vscode-0.1.2.vsix` + `.sha256`
- `eudkit-zed-0.1.2.tar.gz` + `.sha256`
- the four `eudkit-lsp-*` assets + `.sha256` companions
- the four `eudkit-*` CLI assets + `.sha256` companions
- `BINARY-SIZES.txt`

Every binary and editor artifact has a published SHA-256 companion. Downloads
without a valid companion are rejected.

## Version compatibility

The editor contract is unchanged:

> Editor extension `0.1.x` accepts `eudkit-lsp` `0.1.x`. Patch releases stay
> compatible within the series. A `0.2.x` server requires a matching extension
> update.

VS Code runs `eudkit-lsp --version` at runtime and rejects a mismatch. Zed
enforces the same rule structurally: the download URL and cache are pinned to
the extension package version (`0.1.2` → `v0.1.2`) and the SHA-256 companion is
mandatory.

## Installation

- **VS Code:** download `eudkit-vscode-0.1.2.vsix`, verify its checksum, and run
  `code --install-extension eudkit-vscode-0.1.2.vsix`. No Rust is required; the
  extension downloads and verifies `eudkit-lsp` on first use.
- **Zed:** download `eudkit-zed-0.1.2.tar.gz`, verify its checksum, and install
  it with **Install Dev Extension**. See the
  [user guide](../eudkit-lsp-user-guide.md) for the full walkthrough.

## Known limitations

The canonical list is in the [user guide's MVP exclusions](../eudkit-lsp-user-guide.md#mvp-exclusions).
Release-facing highlights:

- Hover and signature help cover only canonical/Map Context symbols and the
  supported eudkit calls. They do not provide general API types or type
  checking; Pylance and tsserver remain responsible for those.
- Per-map `.d.ts`/`.pyi` generation and inline compiler diagnostics remain out
  of scope for the editor MVP.
- There is no map-path setting; `eudkit-lsp` discovers `eudkit.toml` from the
  document path.
- Custom `UNIx` names are accepted by diagnostics when a map is loaded but are
  not added to `KillUnit` completion.
- Zed ships as a dev-extension source archive, not a registry package.
- Zed's rendering of completion/hover/signature UI was not independently
  driven in the acceptance pass; the shared server responses are covered by
  protocol tests. See the
  [acceptance matrix](../eudkit-lsp-acceptance-matrix.md).
